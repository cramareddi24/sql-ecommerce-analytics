# E-commerce SQL Analytics

Nine SQL queries that answer real business questions for a fictional online retailer: revenue trends, product profitability, customer retention, return rates, and channel performance.

The goal was to practice the SQL I'd actually use as an analyst, starting from a business question and working back to the query, not just writing syntax for its own sake. Every query file starts with the question it answers.

> All data is synthetic, generated by `scripts/build_database.py` into a local SQLite database (800 customers, 35 products, about 2,100 orders across Jan 2024 to Jun 2025).

## Questions answered

| # | Business question | SQL techniques |
|---|---|---|
| 01 | How is net revenue trending month over month? | CTE, `LAG()` |
| 02 | Which products drive revenue, and how profitable are they? | Multi-table joins, calculated margin |
| 03 | What share of revenue and profit does each category contribute? | `SUM() OVER ()` |
| 04 | Who are the top 3 customers in each region? | `RANK() OVER (PARTITION BY ...)` |
| 05 | Which acquisition channels bring customers who come back? | `LEFT JOIN`, conditional counts with `CASE` |
| 06 | How many customers from each quarterly cohort return within 3 and 6 months? | Cohort analysis, date arithmetic |
| 07 | Which categories have the highest return rates, and what does that cost? | `CASE` in aggregates, `HAVING` |
| 08 | What's revenue year to date, and what's the 3-month trend? | Running total, moving average window frame |
| 09 | Does average order value differ by sales channel? | Two-level aggregation, pivot with `CASE` |

## What the data showed

- **Revenue share isn't profit share.** Electronics brings in 33% of revenue but only 24% of gross profit. Apparel matches that profit on about half the revenue because of much higher margins (~53% vs ~29%).
- **Apparel has a return problem.** Orders containing apparel are returned 16.4% of the time, roughly double every other category. That's about $9.5K in returned revenue, the largest of any category. Better size guidance would likely pay for itself.
- **Email and referral customers are the most loyal.** They repeat at 65 to 68% vs 54% for social. Worth weighing against acquisition cost before shifting budget toward social.
- **Seasonality is sharp.** November revenue jumped 103% over October, then January fell 55% from December. Staffing and inventory plans should account for that swing.
- **Data caveat:** the 2025-Q2 cohort shows low retention only because the dataset ends in June 2025, so those customers haven't had time to return yet. I flag this instead of reading it as a real drop.

## Schema

```
customers (customer_id, first_name, last_name, email, region, signup_date, acquisition_channel)
products  (product_id, product_name, category, unit_price, unit_cost)
orders    (order_id, customer_id -> customers, order_date, sales_channel, status)
order_items (order_item_id, order_id -> orders, product_id -> products, quantity, unit_price, discount)
```

Net revenue is calculated as `quantity * unit_price * (1 - discount)` on completed orders only. Full DDL in [schema.sql](schema.sql).

## How to run

```bash
pip install -r requirements.txt

# Build the SQLite database
python scripts/build_database.py

# Run all queries and write outputs/query_results.md
python scripts/run_queries.py

# Or run any single query directly
sqlite3 data/ecommerce.db < queries/06_cohort_retention.sql
```
